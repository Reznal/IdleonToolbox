# Product Context: IdleonToolbox Gear Loadouts

## Why This Project Exists

### Problem Statement
Idleon players currently lack an efficient way to:
- Plan and save optimal gear configurations for different activities
- Quickly see what gear they own and where it's located
- Compare different loadout options for specific tasks
- Get recommendations for best available gear from their inventory

### Current Pain Points
1. **Manual Gear Planning**: Players must manually track optimal gear combinations
2. **Item Location Confusion**: Difficulty finding where specific items are stored
3. **Limited Sampling Companion**: Current tool only shows ideal gear, not alternatives from owned items
4. **No Loadout Persistence**: Cannot save and recall gear configurations

## How It Should Work

### User Experience Goals

#### Primary Workflow
1. **Access Tool**: Navigate to new "Gear Loadouts" page in tools section
2. **Create Loadout**: Click gear slots to open item selection modal
3. **Select Items**: Choose from owned items with availability indicators
4. **Save Configuration**: Name and save loadout with optional character association
5. **Load Anytime**: Quickly recall saved loadouts for reference

#### Enhanced Sampling Companion
1. **View Recommendations**: See best-in-slot from owned gear
2. **Explore Alternatives**: View ranked alternatives when ideal gear unavailable
3. **Check Requirements**: Filter by character level/class restrictions

### Key User Benefits
- **Time Saving**: Quick access to optimal gear configurations
- **Better Planning**: Visual comparison of different loadout options
- **Inventory Management**: Clear visibility of item locations
- **Goal Setting**: Identify missing pieces for ideal builds

## Target Users
- **Active Idleon Players**: Using IdleonToolbox for progression tracking
- **Min-Max Optimizers**: Players focused on optimal character builds
- **Multi-Character Managers**: Players managing multiple characters with shared gear

## Integration Points
- **Existing Account Data**: Seamlessly works with current character/storage data
- **Current UI Patterns**: Follows established design language
- **Authentication**: Uses existing login system
- **Data Persistence**: Integrates with current save/load patterns
